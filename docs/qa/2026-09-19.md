## BUG-1 — `call()` throws wrong-network outside `try/catch`

**Severity:** P1  
**Where:** `web/src/App.tsx` `call()` (guards at lines 83–85 sit **before** the `try` that `setErr`s).

```ts
if (!account) throw new Error("Connect Adena first.");
if (wrongNet) throw new Error(`Switch Adena to Pearl (${PEARL.chainId}).`);
if (!isPkgPath(market)) throw new Error("Set a valid market package path.");
setBusy(func);
// try { doContractCall ... } catch { setErr(...) }
```

Click handlers use `void call(...)`. Banner can show, but the thrown string never becomes `.err`.

**Repro**

1. `cd web; npm run dev` → http://127.0.0.1:5176
2. Connect Adena on a chain-id **other than** `pearl-1` (SwitchNetwork ignored in `connectAdena`).
3. Confirm banner: `Adena is on {chainId}. Switch to pearl-1.`
4. Tab **Sell** → List, or **Create token** → Create, or **Browse** → Buy (if a row exists), or **My listings** → Cancel.

**Expected:** `.err` = `Switch Adena to Pearl (pearl-1).` Tx not sent.  
**Actual:** unhandled rejection; `setErr` never runs. Banner only.

## BUG-2 — missing `chainId` is treated as Pearl

**Severity:** P1  
**Where:** `web/src/lib/wallets.ts` `connectAdena` return.

```ts
await adena.SwitchNetwork(PEARL.chainId); // catch { /* ignore */ }
return { ..., chainId: d.chainId || PEARL.chainId };
```

`wrongNet` is `account?.chainId && account.chainId !== PEARL.chainId`. A defaulted `pearl-1` never trips it.

**Repro**

1. Adena `GetAccount` omits `data.chainId` **or** `SwitchNetwork` fails and account stays on another network without returning chainId.
2. Click Connect Adena.

**Expected:** wrong-network banner; List/Create/Buy blocked.  
**Actual:** `Wallet connected.`; `wrongNet` false; tx can go to the wrong chain.
