## On-chain (nftv5 + local `gno.land/r/bazaar/nft`)

Functions **exist** on live nftv5 (`pool.gno`): `DepositPool`, `WithdrawPool`, `DepositNftPool`, `WithdrawNftPool`, `PoolOf`, `ListPoolNfts`, `MyPoolShares`.

There is **no** `ListNftPool`. UI correctly calls `ListPoolNfts`.

### Invariants (from realm + tests)

- **Who:** all four writes go through `requireUser` → EOA `IsUserCall` only. Realm caller panics `nft: EOA only`.
- **Deposit GNOT:** collection must exist (`mustCollection`); `OriginSend` `ugnot` amount `> 0` else `nft: pool deposit`. Send denom is native `ugnot`. First deposit mints shares 1:1; later `add = sent * shares / gnot` (min 1). No protocol fee.
- **Withdraw GNOT:** caller’s `lpPos` shares only; over-withdraw / empty pool panics `nft: shares` / `nft: empty pool`. Pays `gnot * shares / shares_total` ugnot back.
- **Deposit NFT:** owner, not listed. Realm takes ownership; `nfts++`. Original depositor stored in `nftPos`. Does **not** mint LP shares.
- **Withdraw NFT:** original depositor only (not a later owner). Not a buy-from-pool.
- **50 bps:** `ProtocolBps() = 50` applies to **Buy / AcceptOffer**, not pool deposit/withdraw. Pool is a per-slug ugnot vault + NFT locker, not an AMM.

Tests: `TestDepositWithdrawPool`, `TestPoolAbuse` (zero send, over-withdraw, wrong caller, EOA), `TestDepositWithdrawNftPool`, `TestNftPoolAbuse` (listed, not owner, EOA). Happy + abuse present. No test for unknown slug, wrong denom, or second-LP share math.

Live Pearl: every queried slug is empty `0|0|0`. No one has deposited.
